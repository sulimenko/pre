# Partner Finance — Pre-IPO Landing (Vue 3)

T-171: адаптивный черновой макет Partner Finance на Vue 3 / Vite, продолжение согласованного baseline `20a1458`. Это каркас для проверки структуры и содержания; финальный дизайн и сложные scroll-анимации выполняются позже.

## Запуск

Из папки проекта:

    npm start

Команды выполняются из корня репозитория с установленными зависимостями. Vite откроет браузер на http://127.0.0.1:5178/ и будет обновлять Vue/CSS/JS через HMR. Остановить сервер: Ctrl+C. Скрипты и зависимости проекта сохранены.

## Проверка сборки

```sh
npm run build
npm run preview
```

## Архитектура

- `src/App.vue` — плавающее меню, ровно 10 основных секций и уведомление о неподключённых действиях.
- `src/draft/` — компоненты макета, данные текстовых сценариев и адаптивный `styles.css`.
- `src/data/companies.js` — существующий источник пяти компаний: Polymarket, Apptronik, Lambda, Perplexity, SambaNova. Карточки рендерятся через `v-for`; шестая компания не требует изменения разметки. Для минимальной суммы используется `company.minimum`, если оно задано, иначе общий `MIN`.
- `src/main.js` — подключение только стилей текущего макета и запуск Vue.
- `src/components/`, `src/composables/`, `src/styles.css`, `landing-a-v3.html`, `assets/`, `public/assets/` — сохранённые исходные компоненты и активы. Старые секции, модальные окна и кинематографические эффекты в текущей странице не подключены.

Порядок секций: Hero → Что доступно сейчас → Почему Pre-IPO сейчас → Уже в терминале → Рынок IPO → Быстро. Прозрачно. Просто. → Trust → Видео → FAQ → Финальный CTA. Юридический текст находится внутри последней секции.

## Что можно проверить в макете

- Меню и Hero CTA переходят к секциям; мобильное меню открывается кнопкой и закрывается по выбору ссылки или Escape.
- Шесть кнопок терминала меняют активное описание, номер шага и подпись заглушки. Это сценарий будущей прямой Pre-IPO торговли.
- Три стадии «Быстро / Прозрачно / Просто» меняют текст и заглушку PBull. Доступные сейчас регистрация, обычные сделки и портфель отделены от будущей Pre-IPO функции.
- FAQ раскрывается кнопками, в том числе с клавиатуры. Фокус виден, `prefers-reduced-motion` отключает плавную прокрутку.
- CTA без URL имеют видимую подпись «Подключим позже». Нажатие показывает только пояснение: операции не выполняются. Форм, запросов в CRM/API и экранов успешной отправки нет.

Цены, минимумы и статусы каталога — черновые данные прежнего источника, их нужно подтвердить перед публикацией. Робот — текстовая заглушка «РОБОТ АПТРОНИК». Лицензии, инфраструктура, цепочка проверок пополнения и видео представлены помеченными примерами, а не подтверждёнными сведениями. IPO-блок не содержит выдуманной статистики; выход на биржу не гарантирован.

## Handoff: какие реальные материалы нужны от пользователя

Пожалуйста, предоставьте следующие **реальные скриншоты PBull** без персональных данных. Для каждого нужен исходный файл и пояснение, что показано: текущая функция или будущая функция после её реализации. Один файл можно использовать повторно, если он подходит для нескольких мест.

### Hero — 2 экрана

1. Десктопный терминал Partner Finance / PBull: полный основной интерфейс с реальными доступными функциями, без добавленных в редакторе Pre-IPO элементов.
2. Мобильный каталог Pre-IPO с Apptronik, Polymarket, Lambda, Perplexity и SambaNova — только после появления такого экрана в продукте. До этого сохраняем заглушку будущего экрана.

### Демонстрация терминала — 6 экранов

1. Выбор компании: мобильный список Pre-IPO предложений.
2. Условия: открытая карточка Apptronik с ценой, минимумом, доступным объёмом и основными данными.
3. Заявка: ввод суммы и просмотр параметров перед размещением.
4. Статус исполнения: реальные поддерживаемые статусы заявки; Pending / Confirmed / Completed используются в макете только как пример.
5. Уведомления: реальное обновление заявки, распределения или подтверждения сделки.
6. Портфель: реальная Pre-IPO позиция / holdings с фактически отображаемыми данными.

Эти шесть Pre-IPO экранов нужны после реализации функции. Пока она не доступна, оставляем помеченные placeholders; реальные экраны обычных сделок не выдаём за Pre-IPO.

### Процесс PBull — регистрация, KYC, документы, пополнение, покупка, портфель

1. Установка: реальная страница приложения в магазине или экран первого запуска.
2. Регистрация / открытие счёта: начало и фактический экран заполнения данных.
3. KYC: экран проверки личности и экран фактического статуса проверки.
4. Документы: список документов, просмотр документа и экран подписания.
5. Пополнение: выбор способа, реквизиты / инструкции, статус перевода и баланс после зачисления.
6. Покупка обычного доступного актива: карточка актива, цена / условия, ввод параметров, проверка заявки и реальный экран результата. Нужна запись обычной сделки; Pre-IPO сценарий добавляется только после запуска соответствующей функции.
7. Портфель: общий список позиций и открытая позиция со статусом и стоимостью.

Для будущих анимаций также нужны реальные короткие screen recordings этих последовательностей. Не генерируем интерфейсы, не дорисовываем отсутствующие функции и не подменяем реальные скриншоты.
